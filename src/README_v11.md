## 二、两个 bug 的来龙去脉

### bug 1：标注图显示为破图

前端 `index.html`：

```js
state.resultUrl = `data:image/jpeg;base64,${data.annotated_image}`
```

后端 `webapp.py` 又返回了 `data:image/jpeg;base64,xxxx` → **双层前缀** → 浏览器无法解析。

v9 的 README 声称「移除重复拼接的 data URL 前缀」，但 `index.html` 与 v8 逐字节相同，**改动从未落地**。v10 同样保留。

**v11 修法**：后端只返回纯 base64（与前端契约一致）。

### bug 2：掩码归一化尺寸错误（影响最大）

`ultralytics` 的 `results.masks.data` 分辨率**不是原图**：

```
图片 1279×1706  →  masks.data 形状 [1, 640, 480]
```

原代码 `mask_to_polygons(mask, w, h)` 用**原图**宽高做归一化，
导致 480 宽的掩码被除以 1279 → 坐标整体压缩到左上角。

修复前评测结果：

```
平均 IoU      : 0.0095
IoU>=阈值 命中 : 0 / 30
```

修复后：

```
平均 IoU      : 0.6605
IoU>=阈值 命中 : 34 / 40
精确率        : 0.667
召回率        : 0.850
F1            : 0.747
```

**同一个模型，只改归一化方式，IoU 从 0.01 涨到 0.66。**

> 这也解释了 11 月 17 日那次「模型把墙面当禁停区」的误判——当时看到的多边形位置错误，
> 有相当一部分是这个坐标 bug 造成的，不全是模型的问题。

## 四、v10 继承下来的工程加固

| 项 | 说明 |
|---|---|
| 请求体大小 / 像素上限 | 防止超大图打爆内存 |
| 真实图片格式校验 | 不只看 MIME，解码后校验 |
| 区域参数前置校验 | 坐标越界、重复名、无效停留时间都在判定前拒绝 |
| **推理锁** | 多请求串行，避免同一模型实例并发调用 |
| 类别白名单 `auto` | 通用模型返回的人/汽车不再计入非机动车 |
| 静态文件路径关系校验 | 防目录穿越 |
| 启动脚本三层回退 | `.venv` → `D:\yolo_env` → `py -3` |
| 环境变量 | `CAMPUS_BIKE_MODEL` / `CAMPUS_ZONES_MODEL` |
